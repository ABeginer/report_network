Overview
Goal: Understand CSRF attacks and countermeasures.
Context: CSRF attacks exploit a victim's active session with a trusted site to execute unauthorized actions via a malicious site.
Tools: Open-source Elgg social networking platform with disabled CSRF protections for educational purposes.
Lab Environment Setup
Environment: Uses Docker containers to host:
Vulnerable Elgg site (www.seed-server.com).
Attacker’s site (www.attacker32.com).
Defense site (www.example32.com).
Key Setup Steps:
Download pre-configured files.
Use Docker commands to set up containers.
Configure hostnames in /etc/hosts.
Lab Tasks
Attacks
Task 1: Observing HTTP Requests

Use tools (e.g., HTTP Header Live) to examine GET and POST requests on Elgg.
Identify parameters involved.
Task 2: CSRF via GET Request

Craft a URL that exploits an active session to execute an unauthorized friend request.
Explore the use of HTML tags like <img> for silent GET requests.
Task 3: CSRF via POST Request

Modify a victim’s profile using a forged POST request.
Employ JavaScript to automate form submission from the attacker's site.
Defenses
Task 4: Enabling Elgg's CSRF Countermeasures

Reactivate Elgg's token-based defense mechanism.
Test attack effectiveness post-activation.
Task 5: Experimenting with SameSite Cookies

Test cookie behavior (Normal, Lax, Strict) with cross-site and same-site requests.
Analyze how SameSite properties mitigate CSRF risks.
Guidelines
Tools:
Firefox add-ons (e.g., HTTP Header Live) for analyzing HTTP traffic.
Developer tools for debugging JavaScript.
Instructions:
Detailed steps to observe, debug, and craft requests.
Submission: Write your own walk-through for the wargame and submit it as a single PDF file named name_id_l6.pdf.
